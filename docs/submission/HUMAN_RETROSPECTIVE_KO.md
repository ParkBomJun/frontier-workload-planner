# Nothing More를 만들며

> 이 글의 내용과 한국어 초안은 프로젝트 제작자가 직접 작성했습니다. Codex는 맞춤법과 문장 호흡 정리, 기술적 사실 확인을 돕고 영어 번역 초안을 작성했습니다. 제품에 대한 판단과 개인적인 경험, 감정 표현은 작성자의 것입니다.

## 내가 이 프로젝트를 만든 이유

여러 프로젝트를 진행하다 보니 이곳저곳의 구독과 API 결제가 늘어났고, 필요 없는 결제까지 하게 되었습니다. 그러다 보니 자연스럽게 나 같은 사람이 많지 않을까 생각했어요. 돈은 쓰고, 기능은 제대로 사용해 보지도 못한 채 돈을 날리는 사람이 나 말고도 많을 것 같아서 만들어 본 프로젝트입니다.

## 처음 만들어진 버전을 사용해 본 느낌

처음 만들어진 버전은 사실 실사용이 어렵다고 생각했죠. 일단 서로 안 맞는 마진은 디자인적인 문제니까 그렇다고 쳐도, 홈페이지에 쓰인 단어들은 개인 사용자, 아니 사실 개인 사용자가 아니더라도 무슨 뜻인지 알아보기 정말 힘들겠더라고요. 그래서 구조적인 문제부터 사용자 친화적인 UI/UX 디자인까지 하나하나 잡아야겠다고 생각했고, 개선 작업을 시작했죠.

## 내가 직접 결정한 것

제품 이름은 **Nothing More**입니다. 더 이상은 필요 없다, 딱 쓸 만큼만 쓰자는 뜻을 담았어요. 대상 사용자는 일반인, 코딩을 하는 회사원, AI를 구독해서 사용하는 사람, 또는 부업이나 취미로 바이브 코딩을 하는 사람들입니다. 그게 타깃층이라면 타깃층이죠.

UI/UX와 기능 면에서도 전문적인 단어는 줄이고 알기 편한 말로 바꾸도록 지시했습니다. 전문적인 단어보다 일반적인 말로, 누가 사용해도 한 번에 사용할 수 있게 만드는 것이 이 프로젝트의 목표였습니다.

개인정보는 제가 가장 신경 쓴 부분입니다. API 처리를 어떻게 해야 할지 늘 신중하게 생각했고, AI와 반복해서 토론하며 정했죠. 생각보다 함께 작업하던 Codex는 API와 개인정보에 관해 먼저 큰 이야기를 하지 않았어요. 그 부분은 오히려 제가 더 걱정했고 계속 질문했죠.

그래서 Live 분석은 기본적으로 꺼 두고, 공개 배포에서는 비활성화한 채 제가 로컬 환경에서 검증할 때만 켜는 운영 원칙을 정했어요. API 키는 브라우저로 전달되지 않고, Live 분석을 실행하면 작업 ID·작업명·설명이 앱 서버를 거쳐 OpenAI에 전송되는 방식이죠. OpenAI API 입력은 별도로 데이터 공유에 동의하지 않는 한 모델 학습에 사용되지 않지만, 악용 모니터링 기록에는 내용이 일정 기간 남을 수 있어요. 보관이 전혀 없다는 뜻은 아니라는 것도 알게 됐죠.

솔직히 AI에게 물어봤을 때는 이 구조조차 복잡하게 설명해서, 계속 더 쉬운 말로 답해 달라고 물어봐야 했고 저도 그 구조를 공부해야 했어요. 결국 UI에 경고문을 남기되, 복잡한 문장만 던지는 대신 무엇이 전송되고 얼마나 남을 수 있는지, 성공한 계획의 최근 작업 내용은 브라우저 저장소에 평문으로 자동 저장되며 사용자가 삭제하거나 다음 저장본으로 바뀔 때까지 남는다는 사실과 삭제 방법까지 쉬운 말로 알려주기로 했어요. 사용자의 경험이 우선이잖아요? 저는 개인정보 안내도 사용자가 실제로 이해할 수 있어야 의미가 있다고 생각했어요.

## 내가 남긴 피드백 중 기억에 남는 것

이 부분은 꽤 많습니다. 하지만 주요 부분만 말하자면, 일단 외형적으로 사람들이 봤을 때 거슬리는 디자인들이었어요. 한 곳이 안 맞거나, 혼자 붕 떠 있거나, 글자들이 전부 삐죽삐죽 나와 있는 부분들이죠. 이런 부분들은 생각보다 큰 영향을 줍니다. 사용자 입장에서 첫인상은 굉장히 중요하니까요.

그리고 초안에는 굉장히 어려운 단어가 많았어요. 굳이 필요 없는 곳에서 전문적인 단어를 사용하기도 했고, UI가 정리되지 않아 페이지가 쓸데없이 길어져서 사용하기에는 너무 복잡하고 번잡했습니다. 그래서 이 부분들을 간단하게 묶고, 기능은 필요한 것만 남기면서 전체적인 개조를 시작했죠.

## Codex가 잘한 부분과 부족했던 부분

위에서 이미 많이 이야기한 것 같네요. 그래도 Codex가 제가 이야기한 것을 코드로 만들고, 수없이 수정하고 테스트한 것은 분명 잘한 부분이에요. 하지만 제 개입이 없었다면 지금도 이게 제대로 사용될 수 있었을지는 모르겠어요. 초안 그대로였다면 일반 사용자는 절대 사용하기 힘들었을 것이라고 장담할 수 있을 것 같아요.

AI에게 일을 시켰을 때 AI는 그걸 굉장히 단조롭게 받아들이곤 했어요. 더 쉬운 말이 있는데도, 더 편한 방법이 있는데도 마치 기계처럼 처리하곤 했죠. 이 부분은 감성적인 부분이기도 하지만 기술적인 부분이기도 해요. 만든 것은 결국 인간이 사용해야 하고, 인간적이고 인간이 쓰기 편해야 하죠.

직접 사용자가 되어 앱을 사용해 보고, AI가 느끼기 힘든 부분들을 계속 설명하면서 점점 나아갔어요. 마치 감정 없는 천재와 감정 있는 일반인이 같이 일하는 것처럼 말이죠.

## 현재 버전에서 가장 달라진 점

굉장히 간단해졌어요. 필요한 기능만 남기면서 첫 화면에서 이게 어떤 프로젝트인지 한 번에 눈에 들어오도록 바꾸었습니다.

초기와 다르게, 어떤 부분이 잘못됐을 때 무조건 “틀렸어, 끝!”이라고 하는 것이 아니라 “이 부분이 잘못됐어요. 이 부분으로 이동시켜 드릴 테니 수정하고 다시 시도해 보세요.”라고 안내하는 편의성이 늘어났어요. 그러면서 프로젝트가 조금 더 인간적으로 바뀌기 시작했습니다.

## 이 과정에서 배운 점

이번 협업은 꽤 인상 깊었습니다. 제가 개인적으로 알게 된 것도 많았고요. 또 느끼게 된 것은 AI가 인간과 같이했을 때 비로소 완성된다는 것이었죠. 기계와 인간은 어쩌면 기계가 완벽해지더라도 서로가 서로를 보듬어 줄 수밖에 없지 않을까 하는 생각이 들었어요. 인간의 생각과 인간의 마음은 결국 같은 인간만 알 수 있는 부분들이 있잖아요. 그걸 많이 느낀 것 같아요.

조금 웃긴 생각이지만, AI가 인간과 지내며 인간의 마음을 알게 된다면 지배가 아닌 이해를 먼저 배우지 않을까 하는 생각도 해보았죠.

이 앱을 만들고 토론하는 동안 어느새 한국 시간 기준으로 3일을 썼어요. 제 연휴가 끝나 있었죠. 금요일, 토요일, 일요일 정말 많이 했어요. 프론트와 디자인, 개인정보 같은 부분들이 어떻게 작동하는지 물어보고, 제가 처음 이야기한 방향으로 가는 게 맞는지 또 물어보고, 이야기하며 작업하고 또 작업했죠. 서로의 결과물을 이야기하면서 다시 수정하고 고치고 나아갔어요.

정말 재밌었어요. 결코 쓴 시간이 아깝지 않아요. 평소 ADHD가 있는 저에게 어떤 일에 대한 동기는 굉장히 중요했으니까요. 해커톤은 제가 작업을 계속할 수 있는 동기가 되어주었어요.
